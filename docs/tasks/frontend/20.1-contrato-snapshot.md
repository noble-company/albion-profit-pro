# 20.1 — Contrato de snapshot de preços atuais

## Objetivo

Definir o contrato que representa uma leitura concluída do livro do Albion. O contrato será a
base comum do client Go, ingest, PostgreSQL, Redis e todas as APIs que calculam preço atual.

## Escopo do snapshot

Um snapshot é identificado por:

```text
realm + market_id + item_id + quality_level + enchantment_level + auction_type
```

`auction_type` é `offer` (ordem de venda) ou `request` (ordem de compra). O `market_id` preserva
a identificação do mercado específico, inclusive Black Market e mercados adicionais da mesma
cidade. A cidade legível continua sendo resolvida pela tabela de localizações.

## Payload lógico

O transporte continuará autenticado e versionado, mas o payload passará a carregar uma leitura
completa, além das ordens:

```json
{
  "SnapshotId": "uuid",
  "CapturedAt": "2026-08-24T12:30:00Z",
  "CompletedAt": "2026-08-24T12:30:01Z",
  "Scope": [
    {
      "MarketId": "5003",
      "ItemId": "T5_MAIN_FIRESTAFF",
      "QualityLevel": 2,
      "EnchantmentLevel": 0,
      "AuctionType": "offer"
    }
  ],
  "Orders": []
}
```

`Orders: []` é válido quando a leitura foi concluída e não existem ofertas. Isso é necessário
para remover do estado atual uma oportunidade que deixou de existir.

## Regras de validade

- `SnapshotId` é UUID e é idempotente dentro do realm.
- `CapturedAt` e `CompletedAt` são timestamps UTC; `CompletedAt` não pode ser anterior a
  `CapturedAt`.
- Um snapshot só reconcilia ordens depois de marcado como concluído.
- O escopo precisa ser explícito; não é permitido inativar ordens de uma cidade, qualidade ou
  lado que não esteja listado em `Scope`.
- Uma ordem recebida sem snapshot continua aceita apenas no caminho legado, marcado como parcial,
  e não pode inativar ordens existentes.
- Snapshot atrasado, com `CompletedAt` anterior ao snapshot ativo do mesmo escopo, é ignorado para
  leitura, mas pode ser registrado para diagnóstico.
- IDs de ordem continuam sendo a identidade do leilão: `realm + source_id`.

## Semântica de leitura

As APIs de preço atual e os motores de Flip, Refino, Craft e Calculadora devem usar somente
ordens ativas do snapshot mais recente de cada escopo. Dados anteriores continuam disponíveis
para histórico, mas nunca são fallback silencioso de cálculo atual.

Toda resposta que usar preço atual deve expor:

- `snapshot_id`;
- `snapshot_at`;
- `age_seconds`;
- `is_stale`;
- `coverage` (`complete`, `partial` ou `missing`).

Sem snapshot concluído para o escopo, o preço atual é `null`. A interface pode mostrar a última
observação histórica separadamente, mas não pode utilizá-la para calcular lucro atual.

## Compatibilidade e migração

O formato atual `{"Orders": [...]}` permanece aceito como ingest parcial durante a transição.
Ele atualiza preços presentes, invalida cache das combinações recebidas e nunca remove ausentes.
O formato com snapshot será obrigatório quando o client atualizado for distribuído.

## Critérios de aceite

1. O mesmo snapshot processado duas vezes não duplica nem altera o resultado.
2. Snapshot vazio concluído deixa o escopo sem preço atual.
3. Snapshot novo vence o antigo mesmo quando o preço novo é menor.
4. Snapshot atrasado não reverte o preço atual.
5. Escopos diferentes (cidades, mercados, qualidades, encantamentos e lados) não se misturam.
6. Refino, Craft, Calculadora e Market Flip conseguem identificar o snapshot que sustentou o
   cálculo.
